# 문화관 길찾기 데이터

앱에서 사용할 노드·연결 데이터와, 이를 눈으로 확인하는 지도입니다. 원본 PDF, 도면 이미지, 상세 벽체·설비 도형, 원본 픽셀 좌표는 이 묶음에 없습니다. 방 배치를 이해하기 위한 단순 윤곽은 미터 좌표로 포함합니다.

## 처음 볼 때

1. `지도보기.html`을 브라우저에서 엽니다. 설치·서버·인터넷 연결 없이 동작합니다. GitHub 파일 화면에서는 실행되지 않으므로 내려받아 여세요.
2. 호실이나 노드·연결선을 누르면 오른쪽에 ID와 좌표·거리, JSON 항목이 나옵니다.
3. 출발·도착을 고르고 **경로 확인**을 누릅니다. 다른 층은 **층간 후보 사용**을 켜야 시연할 수 있습니다.
4. 앱 개발에서는 `graph.json`을 읽습니다. CSV는 현장 확인 기록용이며 앱 데이터가 자동으로 바뀌지는 않습니다.

HTML은 처음 전달한 JSON 사본을 내장하고 있습니다. `graph.json`을 수정했다면 HTML의 **JSON 불러오기**로 수정본을 선택하세요. 파일은 브라우저 안에서만 읽으며 업로드하지 않습니다. 파일을 다시 열면 최초 내장본으로 돌아갑니다. 보고 있는 데이터 이름과 상태가 화면에 표시됩니다.

## 포함 파일

| 파일 | 용도 |
|---|---|
| `graph.json` | 앱에서 읽을 기준 데이터 |
| `지도보기.html` | JSON만으로 그린 노드 지도·경로·상세 항목 확인 |
| `현장확인표.csv` | 연결 구간별 통행 여부와 실측 거리 기록 |
| `README.md` | 데이터 의미와 사용 규칙 |

## 좌표

- 단위는 m입니다. `x_m`, `y_m`은 도면 치수를 이용해 환산한 **추정값**이며 현장 측량값이 아닙니다. 소수 자릿수가 측정 정확도를 뜻하지 않습니다.
- 원점은 지상층 공통 기준축 X0/Y0 교점, +x는 도면 오른쪽, +y는 도면 위쪽입니다. 방위각·북쪽 기준이 아닙니다.
- HTML은 y축을 뒤집어 화면에 그립니다. 이 표시 변환을 원본 데이터에 적용하지 마세요.
- 층별 기준축은 맞췄지만 `z_m`과 `ar_transform`은 아직 null입니다. `floor`를 높이(m)로 쓰지 마세요.
- ARCore의 좌표계에 넣으려면 현장 기준점·방향·층고를 확인하고 별도 변환을 구해야 합니다.
- 방 윤곽은 배치 이해를 위한 근사 도형입니다. 벽 두께·정확한 문 개구부·방 면적·복도 폭·장애물을 표현한 건축 도면이 아닙니다. 화면의 여백이 통행 가능한 공간을 뜻하지 않습니다.

## 데이터 구조

`nodes`, `edges`, `rooms` 세 목록이 핵심입니다. ID는 문자열로 그대로 사용하세요. `406-1` 같은 호실 번호를 숫자로 변환하지 않습니다.

### nodes

| 필드 | 의미 |
|---|---|
| `id` | 노드 고유 ID |
| `floor` | 지상층 번호 1~5 |
| `type` | `corridor` 복도, `room_door` 문 앞, `room_access` 열린 진입부, `internal_access` 방 내부 통로, `stair_landing` 계단 진입부, `entrance` 건물 출입구 |
| `x_m`, `y_m` | 도면에서 얻은 평면 좌표 |
| `z_m` | 실제 높이. 현재 null |
| `field_verified`, `note` | 현장 확인 여부와 제약 |

### edges

| 필드 | 의미 |
|---|---|
| `id`, `from`, `to` | 연결 ID 및 양 끝 노드 ID |
| `type` | `corridor`, `door_access`, `stair_access`, `internal_access`, `entrance_access`, `stairs` |
| `bidirectional` | true이면 역방향도 허용하는 초안 가정 |
| `plan_distance_m` | 도면 좌표에서 계산한 평면 길이. 층간 연결은 null |
| `distance_m` | 현장 측정 거리. 현재 모두 null |
| `include_in_draft_route` | 초안 경로에 기본 포함할지 여부. 통행 보증은 아님 |
| `status`, `field_verified`, `note` | 근거와 현장 확인 여부 |

### rooms

`room_id`, `floor`, `label`, `category`, `door_node_ids`로 호실과 진입 노드를 연결합니다. 문이 여러 개면 여러 ID가 들어 있습니다. 호실 중심 좌표로 경로를 끝내지 말고 선택한 진입 노드로 연결하세요. `406-1`은 `406` 내부를 통과해야 하는 구획이며 출입 허용 여부는 현장 확인이 필요합니다.

`outline_m`은 방 윤곽 꼭짓점 목록이며 각 점은 `{x_m, y_m}`입니다. 마지막 점에서 첫 점으로 닫아 그립니다. `label_position_m`은 호실 번호를 표시할 위치입니다. `outline_status=approximate_display_only`로 표시했으며, 경로 계산이나 충돌 판정에는 사용하지 않습니다. 이전 JSON에 윤곽 필드가 없으면 HTML은 노드·호실 번호만 표시합니다. 열린 진입 구획은 점선 윤곽으로 구분합니다.

## 경로 계산

1. `include_in_draft_route=true`인 연결로 인접 목록을 만듭니다. `bidirectional=true`이면 역방향도 추가합니다.
2. 같은 층에서는 출발·도착 호실의 진입 노드 조합마다 경로를 구하고 거리 합이 짧은 조합을 선택합니다. Dijkstra 등을 사용할 수 있습니다.
3. 구간 가중치는 **양수인 `distance_m` 우선, 없으면 `plan_distance_m`**입니다. 둘 다 없으면 거리 계산에 사용할 수 없습니다. null을 0으로 바꾸지 마세요.
4. 층간 연결 후보 8개는 기본 제외 상태입니다. HTML의 후보 사용 옵션을 켜면 시연에서만 추가되며 JSON의 확인 상태는 바뀌지 않습니다.
5. 층간 시연은 목표 층 방향으로만 이동합니다. 층 이동 횟수를 먼저 최소화하고, 같은 횟수에서는 알려진 평면 거리 합을 비교합니다. 계단 보행거리와 시간까지 포함한 최단 경로가 아닙니다.
6. 같은 층 경로를 찾을 때 다른 층으로 우회하지 않습니다. 막힌 연결·출입 제한을 확인하면 해당 연결을 제외하세요.

HTML에 표시되는 길이는 평면 구간 길이입니다. 도면 추정과 현장 측정이 섞이면 화면에 혼합이라고 표시합니다. 계단 구간은 길이에 포함하지 않으며 도착 시간도 계산하지 않습니다.

## 현장 확인 후

`현장확인표.csv`의 각 행은 graph.json의 연결 ID 하나와 대응합니다.

- `measured_distance_m`: 양 끝 노드 사이 실제 보행 경로를 측정한 거리. 단위 m.
- `passable`: `yes`, `no`, `unknown` 중 하나로 기록합니다.
- `checked_at`: 확인 날짜. 권장 형식 YYYY-MM-DD.
- `measurement_method`: 줄자·거리계 등 측정 방법.
- `notes`: 잠금, 출입 시간, 문 위치 차이, 가구 등.

확인한 내용은 개발자가 검토해 JSON에 반영합니다. 거리만 측정했다고 좌표·문 위치까지 검증된 것으로 처리하지 않습니다. 층간 연결은 실제 계단 연속성과 통행 여부를 확인한 뒤 활성화하세요. CSV에는 자동 반영 기능이 없습니다.

## 현재 범위와 확인 한계

1~5층 호실 64개, 노드 206개, 연결 209개(층간 후보 8개 포함)입니다. 지하·옥상, 외부·부속계단, 시설실·화장실의 출입 경로, 무번호 공간은 제외했습니다. 모든 `field_verified`는 false입니다.

도면 작성 시점의 현황과 현재 건물이 일치하는지, 문 개방·잠금 상태, 실제 거리·층고, 비전 인식·AR 정렬·실제 도착 판정은 아직 확인하지 않았습니다. 원본 도면을 제외한 파생 데이터이며, 자동 업로드·배포 기능은 없습니다.
