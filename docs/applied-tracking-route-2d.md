# 적용한 개선 사항: 문·계단 추적과 경로 위 2D 매칭

작성일: 2026-11-12

## 1. 모델 추론 사이의 특징점 추적

문·계단을 모델 추론 프레임마다 새로 찾던 처리에 영상 특징점 추적을 연결했다.

- 카메라 영상을 회전 정보에 맞춰 256×256 그레이스케일로 복사한다. 모델 입력과 동일한 정규화 화면 좌표를 사용한다.
- 객체 영역에서 영상 기울기의 최소 고유값으로 특징점을 선택하고, 가까운 점을 제거해 객체당 최대 24개를 유지한다.
- 3단계 피라미드 Lucas–Kanade로 특징점을 추적한다.
- 이전→현재→이전의 앞뒤 추적 오차가 1픽셀 미만인 점을 사용한다. 패치 밝기 오차가 큰 점은 제외한다.
- 특징점 쌍으로 similarity 변환 후보를 만들고, 1.8픽셀 이내의 일치점이 최소 6개이면서 전체의 60% 이상인 경우 객체 영역을 이동시킨다.
- 추적 ID를 문·계단 관측에 저장한다. 모델이 재검출하지 않은 중간 프레임에도 같은 ID의 2D 관측을 전달한다.
- 짧은 추적 실패 뒤 재검출할 때는 박스 겹침과 그레이스케일 히스토그램 유사도를 함께 확인한다.

구현: `TrackingImage.java`, `SparseFeatureFlow.java`, `FeatureLandmarkTracker.java`.

## 2. 임시 후보와 확인된 트랙 분리

문·계단의 연결 요소 추출 하한을 0.45로 두어 임시 추적 후보를 받을 수 있게 했다. 이 후보를 곧바로 위치 보정 근거로 사용하지 않는다.

- 일반 확인 조건: 모델 검출 2회 이상, 정상 특징점 추적 2회 이상, 누적 검출 신뢰도 0.6 이상.
- 높은 신뢰도의 단일 검출은 신뢰도 0.85 이상이며 정상 특징점 추적이 4회 이상 이어져야 확인한다.
- 모델이 다시 확인하지 않으면 신뢰도를 시간에 따라 낮춘다.
- 마지막 모델 검출 후 1.5초, 마지막 정상 추적 후 0.6초를 넘긴 트랙은 제거한다.
- 영상 시각 역전, 0.8초를 넘는 프레임 공백, 입력 크기·회전 변경에서는 영상 추적 상태를 초기화한다.
- 동시에 유지하는 객체 트랙은 최대 12개다.

디버그 화면에는 객체 유형, 추적 ID, 신뢰도, `후보`/`확인`, 2D/3D 상태를 표시한다. 재검출과 영상 추적 관측은 별도 필드로 구분한다.

## 3. 실제 안내 경로를 2D 매칭에 전달

`SemanticLandmarkMap`에 안내 경로의 수평 좌표열을 추가했다.

- 지도에서 선택한 경로를 기존 지도→AR 변환과 같은 좌표계로 전달한다.
- `ArRoutePlan`에서 렌더러에 전달하는 실제 경로 점으로 2D 매칭 경로를 구성한다.
- 이전 형식의 semantic payload에 경로 필드가 없어도, 전달된 경로 점에서 구성한다.
- 결과적으로 화면에 그리는 경로와 2D 매칭의 기준 경로가 일치한다.

구현: `SemanticLandmarkMap.java`, `ArRoutePlan.java`.

## 4. 깊이 없는 경로 위 방향 관측 매칭

`RouteBearingMatcher`를 추가하고 실제 카메라 처리 흐름에 연결했다. 이 매처는 관측된 문의 3D 위치나 Depth를 요구하지 않는다.

### 관측과 이력

- 확인된 문·계단 트랙에서 촬영 시점 intrinsics, 카메라 Pose, 이미지 회전을 사용해 수평 시선을 계산한다.
- 카메라 추적이 유효하고 현재 경로가 있을 때만 처리한다.
- 같은 추적 ID의 관측을 하나의 이력으로 묶는다. 같은 문을 반복해서 본 것을 여러 구조물로 계산하지 않는다.
- 추적별로 최근 6초 안의 최대 6개 시점을 유지한다. 최소 0.2초 간격과 카메라 이동/방향 변화를 확인해 의미 있는 시점을 선택한다.
- 샘플 수가 많아져도 오래된 유효 기준 시점 하나를 보존해, 느리게 걷는 동안 이동 기준선이 사라지지 않게 했다.
- 최소 3개 시점과 0.4m 이상 이동 기준선이 있는 서로 다른 트랙 2개 이상이 필요하다.
- 현재 관측되지 않는 트랙은 최대 2초까지 유지한다. 오래된 이력만으로 보정 확인을 계속하지 않는다.

### 위치 후보 비교

현재 보정 변환으로 계산한 카메라 위치를 안내 경로에 투영하고, 그 주변에서 다음 후보를 비교한다.

| 성분 | 후보 범위 | 간격 |
|---|---:|---:|
| 경로 진행 거리 변화 `s` | ±1.25m | 0.25m |
| 경로 좌우 편차 변화 `d` | ±0.6m | 0.3m |
| 회전 변화 `yaw` | ±6도 | 2도 |

- 전체 이동 보정 1.5m, 전체 회전 보정 10도 범위를 유지한다.
- 현재 위치 주변 15m 이내의 사용 가능한 문·계단 기준점 중 최대 16개를 비교한다.
- 같은 추적 ID는 여러 시점에 걸쳐 같은 지도 기준점에 대응한다. 서로 다른 트랙을 같은 기준점에 중복 대응하지 않는다.
- 각 후보에서 지도 기준점이 보여야 하는 방향과 실제 관측 방향을 비교한다. 큰 오차의 영향을 줄이는 Huber 비용을 사용한다.
- AR 상대 위치와 현재 보정에 가까운 후보를 약한 사전 제약으로 사용한다.
- 경로 끝, 회전 코너 주변, 경로에서 크게 벗어난 위치는 보류한다.

### 결정 가능한 성분만 보정

방향 관측 오차에서 계산한 후보별 상대 가중치로 `s`, `d`, `yaw`의 분산을 구한다. 이 가중치는 후보 비교용이며 현장 데이터로 보정된 통계적 신뢰 확률은 아니다.

- 표준편차가 진행 거리 0.3m, 좌우 편차 0.2m, 회전 1.4도 미만인 성분을 선택한다.
- 탐색 범위의 끝에 몰린 후보는 해당 성분을 확인한 것으로 보지 않는다.
- 선택한 성분만 적용해 다시 계산한 방향 잔차도 검사한다. 서로 결합돼서만 맞는 변환을 독립적인 성분 보정으로 적용하지 않는다.
- 방향 RMS 잔차 3도 이하, 기존 변환 대비 의미 있는 오차 감소를 요구한다.
- 서로 다른 이동 시점 3회에서 일관된 변환을 확인한다. 같은 위치에서 재평가하는 것으로 확인 횟수를 늘리지 않는다.
- 최종 목표 변화는 한 번에 이동 0.3m, 회전 1도 이내로 제한한 뒤 기존 경로 보정 관리자로 전달한다.

긴 복도에서 진행 위치를 결정할 근거가 부족하면 해당 성분은 그대로 유지한다. 후보가 여러 곳에 퍼지거나 서로 다른 성분을 분리해 결정할 수 없으면 `AMBIGUOUS`로 보류한다.

## 5. 기존 보정·비동기 카메라 처리와 결합

- 기존 ARCore Session과 Frame을 사용한다.
- 카메라 복사 작업은 100ms보다 자주 제출하지 않고, 모델 추론 간격은 기본 500ms로 유지한다. 이는 제출 간격의 상한이며 실제 기기에서 항상 10fps 추적을 보장하는 수치는 아니다.
- 한 작업 스레드에서 한 작업만 진행한다. 모델이나 추적이 실행 중이면 새 프레임을 쌓지 않는다.
- 모델 추론 프레임 사이에는 그레이스케일 특징점 추적과 경로 2D 매칭을 실행한다.
- Depth 복사는 모델 프레임에서 수행한다. 중간 추적 관측에 이전 Depth나 이전 3D 좌표를 현재 측정값처럼 붙이지 않는다.
- 기존 metric 구조물 매칭이 확인된 경우 사용하고, 새 2D 매칭도 확인됐는데 두 변환이 충돌하면 `CONFLICT_METRIC_AND_ROUTE_BEARING`으로 보류한다.
- 모델·경로·화면 생명주기가 초기화될 때 새 추적기와 2D 매처의 상태도 초기화한다.
- 보정 변환은 기존 경로 렌더링과 경유점 진행 판단에 동일하게 적용한다.
- 2D 매칭 잔차는 라디안(`rad`), 기존 metric 매칭 잔차는 미터(`m`)로 구분한다.

디버그 화면에는 확인된 영상 트랙 수와 경로 2D 매칭에 유지 중인 트랙 수를 추가했다. 추적 표시는 각 관측의 촬영 시점 이미지 변환을 사용한다. 모델 마스크는 새 모델 결과가 도착할 때만 다시 만든다.

구현: `SegmentationController.java`, `SemanticFusion.java`, `LandmarkObservation.java`, `MatchResult.java`, `HelloArActivity.java`, `SegmentationDebugOverlay.java`. 기존 삼각측량의 관측 연결에도 추적 ID를 전달했다.

## 6. 적용 코드 검증

### 빌드와 단위 테스트

`testDebugUnitTest`, `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug`를 실행했다. 최종 단위 테스트 119개가 통과했다. Lint 오류는 0개다.

추가 검증 내용:

- 실제 이동량을 넣은 이미지에서 앞뒤 특징점 추적과 변환 복원.
- 모델 재검출 사이의 같은 추적 ID 유지, 가려진 프레임을 관측 근거로 사용하지 않기.
- 낮은 신뢰도 후보가 영상에서 추적되더라도 확인 상태로 바로 승격하지 않기.
- Depth 없는 여러 시점의 방향 관측으로 경로 진행 위치 보정.
- 느린 이동에서 과거 기준 시점을 보존해 이동 기준선 확보.
- 정지 카메라, 한 추적 ID 반복, 진행 위치가 결정되지 않는 배치의 보정 보류.
- 추적 손실·경로 부재의 보정 차단.
- metric 보정과 2D 보정 충돌 시 적용 차단.
- 이전 형식의 지도 payload에서도 렌더러와 동일한 경로 전달.

### 같은 문화관 영상

`2Fto1F`의 검증된 10fps 비교 사본 1,181프레임과 기존 동일 ONNX의 2Hz 마스크를 사용했다. 추적과 2D 매칭은 앱의 Java 소스를 그대로 PC에서 컴파일해 실행했다.

- 확인된 시각적 트랙이 있는 프레임: 48개.
- 그중 모델 재검출 없이 추적만으로 확인 관측이 이어진 프레임: 38개.
- 이 영상 시험의 경로 2D 보정 승인: 0회.
- 서로 다른 이동 트랙 두 개를 충분히 확보하지 못해 보류했다.
- 별도의 합성 방향 관측 대조군에서는 경로 2D 보정이 실행됐다. 이 대조군은 실제 영상에서 알아낸 위치가 아니다.

영상 시험의 카메라 위치·방향·intrinsics는 가정 값이다. 위 프레임 수는 추적 ID의 정답률이나 현장 위치 정확도를 의미하지 않는다. 이번 적용으로 실제 문화관의 위치 오차가 줄었다고 기록하지 않는다.

시험 도구: `model-tests/ade20k/route_bearing_replay.py`, `java/RouteBearingVideoReplay.java`.
