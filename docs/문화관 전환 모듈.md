# 문화관 실내·실외 전환 모듈

수정일: 2026-11-18

상세 설계와 실제 전환 프레임은 [전환 모듈 설계 명세서](전환%20모듈%20설계%20명세서.md)를 참고하세요.

## 1. 무엇을 하는 앱인가요?

**숭실대학교 문화관의 실내 사진과 카메라 화면을 비교해 `실내` 또는 `실외`를 표시하는 앱**입니다. 프로젝트 폴더는 `Entrance_Transition`입니다.

카메라 위에는 세그먼테이션 결과를 반투명 색으로 표시합니다. 세그먼테이션은 화면을 벽·바닥·천장·계단 같은 영역으로 나누는 작업입니다. 벽은 분홍, 바닥은 초록, 천장은 보라, 계단은 노랑, 문은 주황, 하늘은 파랑으로 보입니다.

## 2. 어떤 기준으로 판정하나요?

실내 기준은 [gate1](../assets/gate1.jpeg), [gate2](../assets/gate2.jpeg), [gate3](../assets/gate3.jpeg), [gate4](../assets/gate4.jpeg)입니다. 현재 화면을 네 사진의 구조와 각각 비교하고, **가장 높은 유사도를 실내 점수로 사용**합니다.

```text
실내 점수 = max(gate1 유사도, gate2 유사도, gate3 유사도, gate4 유사도)
```

| 조건 | 화면 표시 |
|---|---|
| 실내 점수 0.75 이상 | 즉시 `실내` |
| 실내 점수 0.75 미만 | 즉시 `실외` |
| 시작 직후, 구조를 충분히 읽지 못함, 오류, 2초 넘게 새 결과 없음 | `판정 중` |

실외 점수는 계산하지 않습니다. 연속 프레임 대기나 진입 확인 버튼도 없습니다. 점수가 0.75 아래로 내려가면 다시 실외로 표시됩니다.

점수는 계단의 유무만으로 정하지 않습니다. 화면을 4×4로 나눠 **영역의 위치·비율 60%와 영역끼리 맞닿은 관계 40%**를 비교합니다. 모델이 자신 있게 구분하지 못한 픽셀은 제외합니다. 픽셀 분류 확률의 제외 기준은 0.35이며, 실내 전환 기준 0.75와는 다른 값입니다. 실내 점수 0.75는 ‘실내일 확률 75%’라는 뜻이 아닙니다.

## 3. 어떻게 실행하나요?

1. Android Studio에서 **`Entrance_Transition` 폴더**를 엽니다.
2. Gradle JDK를 **전체 JDK 21**로 선택하고 프로젝트를 동기화합니다.
3. `app`을 Android 7.0 이상 기기에 실행합니다.
4. 카메라 권한을 허용하고 문화관 입구 주변을 비춥니다.

모델과 기준 데이터는 앱에 포함되어 있어 인터넷이나 API 키가 필요 없습니다. `jlink does not exist` 오류가 뜨면 VS Code 내장 Java 대신 JDK 21을 선택하세요.

APK는 [app-debug.apk](../Entrance_Transition/app/build/outputs/apk/debug/app-debug.apk)에 생성됩니다. 터미널에서 빌드와 검증을 실행하려면 아래 명령을 사용합니다.

```bash
cd Entrance_Transition
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

## 4. 영상으로 실행한 결과

앱과 같은 모델 및 Java 판정 로직을 `video1`, `video2`에 적용했습니다. 결과 영상은 왼쪽 원본, 오른쪽 세그먼테이션, 하단 판정 상태와 실내 점수를 보여줍니다.

| 영상 | 최초 실내 전환 | 결과 |
|---|---|---|
| video1 | 약 19.33초 | 19.67초에는 실외, 20초부터 마지막 관측까지 실내 · [결과 영상](../assets/transition_results_075_gate1to4/video1/video1_transition.mp4) |
| video2 | 약 10.33초 | 마지막 관측까지 실내 유지 · [결과 영상](../assets/transition_results_075_gate1to4/video2/video2_transition.mp4) |

최초 실내 판정의 기준은 두 영상 모두 **gate3**였습니다. 영상과 CSV에는 각 시점에서 가장 높은 점수를 받은 `matchedGate`와 gate1~4 각각의 점수를 기록합니다. [video1 CSV](../assets/transition_results_075_gate1to4/video1/observations.csv), [video2 CSV](../assets/transition_results_075_gate1to4/video2/observations.csv)에서 확인할 수 있습니다.

같은 폴더의 `summary.json`에는 요약, `masks.npz`에는 픽셀별 분류 결과를 저장했습니다. 현재 결과는 `assets/transition_results_075_gate1to4`입니다. `transition_results_075`는 gate1·2만 사용한 이전 결과이고, `transition_results`는 더 이전 판정 규칙의 결과입니다.

영상 실험은 초당 3번 분석한 PC 재생 결과이며, Android 앱 화면을 녹화한 것은 아닙니다. 새 영상 결과를 저장하려면 저장소 루트에서 다음 명령을 실행합니다. Python 추론 환경, JDK, FFmpeg와 로컬 Gradle 캐시의 Gson 2.13.2가 필요하며, Python 패키지는 `Entrance_Transition/tools/requirements.txt`를 참고하세요.

```bash
python Entrance_Transition/tools/replay_videos.py \
  assets/video1.mp4 assets/video2.mp4 \
  --output assets/transition_results_new
```

## 5. 구현 위치와 현재 범위

| 위치 | 역할 |
|---|---|
| `Entrance_Transition/app/src/main/java/com/example/entrancetransition/` | 화면, 카메라, 세그먼테이션 표시, 점수 계산과 전환 판정 |
| `Entrance_Transition/app/src/main/assets/` | SegFormer-B0 ONNX 모델과 문화관 기준 데이터 |
| `Entrance_Transition/tools/` | 모델 준비와 영상 실험 도구 |
| `Entrance_Transition/app/src/main/java/com/example/arnavigation/entrance/` | 모듈 내부에 포함된 마스크·구조 비교·모델 실행 코드 |

전환 모듈은 다른 앱 폴더 없이 단독으로 빌드됩니다. `outdoor_navi`에 남아 있는 GPS·연속 관측 기반 진입 판단기는 이전 별도 구현으로, 현재 독립 앱의 0.75 판정 규칙과 다릅니다.

현재 앱은 **문화관에서 사용자가 촬영한다는 전제의 실험용 판정기**입니다. 건물을 GPS로 식별하거나 실제 문 통과를 확인하지 않습니다. 문 밖에서 실내가 보이거나 다른 장소의 구조가 비슷하면 실내로 표시될 수 있고, 경계 점수에서는 상태가 자주 바뀔 수 있습니다. 실제 문화관 기기 테스트로 정확도를 검증하는 작업은 남아 있습니다.

내비게이션과 실내 위치·층 결정은 아직 연결하지 않았습니다. 화면의 색상은 카메라 영상의 분류 결과이며 `map_node`의 벽 좌표를 투영한 것이 아닙니다. 전체 내비게이션 요구사항은 [PRD](PRD.md)를 참고하세요.
