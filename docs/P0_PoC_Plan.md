# 실외 AR Navigation PoC 기획서

| 항목 | 내용 |
|---|---|
| 문서 상태 | Draft v1.1 |
| 기준 문서 | `docs/PRD.md` |
| 대상 단계 | P0 — Google 경로 기반 실외 AR 내비게이션 PoC |
| 대상 플랫폼 | Android 7.0 이상 (API 24+) |
| 구현 언어 | Java |
| 핵심 기술 | Google Maps SDK for Android, Places SDK, Routes API, GPS, 기기 방향 센서, CameraX |

## 1. 목적

숭실대학교 캠퍼스에서 사용자가 Google 지도에서 목적지를 선택하고, Google Routes API가 제공한 보행 경로의 다음 웨이포인트를 카메라 AR 화살표로 따라 목적지까지 이동할 수 있는 실외 내비게이션 PoC를 제작한다.

이 PoC의 핵심 검증 항목은 다음과 같다.

1. Google 지도에서 현재 위치와 목적지를 확인하고 목적지를 설정할 수 있는가?
2. Google Routes API의 보행 경로를 지도에 표시하고 AR 안내용 웨이포인트로 변환할 수 있는가?
3. 현재 위치와 다음 웨이포인트의 방위를 계산해 휴대폰 방향에 맞는 카메라 AR 화살표를 갱신할 수 있는가?
4. 웨이포인트 통과와 경로 이탈을 판정하고 필요한 경우 Google 경로를 다시 요청할 수 있는가?
5. GPS 또는 방향 신뢰도가 낮을 때 잘못된 안내 대신 안전한 대체 화면을 제공할 수 있는가?

## 2. PoC 범위

### 2.1 포함 범위

- 현재 위치 권한 요청 및 GPS 위치 표시
- Google Maps SDK 기반 2D 지도 표시
- Places SDK 기반 건물·장소 검색
- 지도 탭과 AR 탭을 분리한 하단 탭 구조
- 지도에서 지점을 탭해 목적지 후보 마커 표시
- 선택한 목적지 확정 및 변경
- Routes API 기반 보행 경로, 거리와 예상 시간 조회
- Google 경로를 AR 안내용 웨이포인트 목록으로 변환
- 현재 위치와 다음 웨이포인트 사이의 거리 및 방위 계산
- 카메라 미리보기 위에 다음 웨이포인트 방향 화살표 표시
- 웨이포인트 진행, 경로 이탈 감지와 Google 경로 재요청
- 남은 경로 거리, 다음 행동, 목적지명, 위치 정확도 표시
- 목적지 도착 판정
- 카메라·위치 권한 거부와 저정확도 상태 처리
- 안내 시작, 취소, 도착의 기본 상태 관리

### 2.2 제외 범위

- 실내 내비게이션과 강의실 안내
- ARCore Anchor, VPS 또는 Geospatial Anchor 기반 공간 고정 오브젝트
- 음성 턴바이턴 안내
- 장애물, 공사 구간, 출입 제한 구역을 반영한 경로 탐색
- 서버 기반 사용자 계정, 목적지 동기화, 이동 이력 저장
- 백그라운드 위치 추적

PoC의 화살표는 실제 지면에 고정되는 3D 오브젝트가 아니라 카메라 화면 중앙에 표시되는 **방향 오버레이**다. 최종 목적지의 직선 방향이 아니라 Google 보행 경로의 다음 유효 웨이포인트를 가리키며, 사용자는 언제든 2D 경로 지도로 전환할 수 있어야 한다.

## 3. 핵심 사용자 흐름

```text
앱 실행
  → 지도 탭 표시 및 위치 권한 확인
  → 현재 위치 획득
  → 지도에서 목적지 지점 탭
  → 목적지 후보 마커와 정보 카드 표시
  → [목적지로 설정] 선택
  → Routes API 보행 경로 요청 및 경로 미리보기
  → [AR 안내 시작] 선택 또는 AR 탭 이동
  → 카메라 권한 확인
  → 카메라 화면 + 다음 웨이포인트 화살표 + 남은 거리 표시
  → 위치/방향 갱신에 따라 웨이포인트 진행 및 안내 갱신
  → 경로 이탈 시 Google 경로 재요청
  → 도착 반경 진입
  → 도착 표시 및 안내 종료
```

목적지가 설정되지 않은 상태에서 AR 탭을 선택하면 카메라를 바로 실행하지 않고, “지도에서 목적지를 먼저 선택하세요” 메시지와 지도 탭 이동 버튼을 표시한다.

## 4. 화면 및 탭 구성

앱의 최상위 화면은 `BottomNavigationView`를 사용해 두 탭으로 구분한다.

### 4.1 목적지 검색 탭

#### 화면 구성

- 상단: 화면 제목과 현재 위치 이동 버튼
- 검색 영역: Places 기반 건물·장소 검색과 결과 목록
- 본문: Google 2D 지도
- 지도 요소:
  - 현재 위치 표시
  - 목적지 후보 마커
  - 확정된 목적지 마커
  - Routes API가 반환한 보행 경로선
  - 다음 웨이포인트 마커
- 하단 정보 카드:
  - 선택 좌표 또는 Google 지도에서 얻은 장소명
  - 보행 경로 거리와 예상 시간
  - `목적지로 설정` 버튼
- 목적지 확정 후:
  - `AR 안내 시작` 버튼
  - `목적지 변경` 버튼

#### 상호작용

1. 사용자가 지도를 한 번 탭하면 해당 지점에 후보 마커를 표시한다.
2. 기존 후보가 있으면 새 위치로 이동한다.
3. Places 검색 결과를 선택한 경우에도 같은 후보 마커와 정보 카드를 표시한다.
4. 정보 카드에서 `목적지로 설정`을 누르면 Routes API에 보행 경로를 요청한다.
5. 경로 미리보기에서 `AR 안내 시작`을 누르면 AR 탭으로 이동한다.
6. 목적지 변경 시 기존 경로와 진행 상태를 초기화하고 새 경로를 요청한다.

#### 초기 카메라 위치

- 위치 권한과 현재 위치가 있으면 현재 위치를 중심으로 표시한다.
- 아직 위치를 받지 못했으면 숭실대학교 캠퍼스 중심 좌표를 기본값으로 사용한다.
- 위치 권한이 거부되어도 지도 탐색과 수동 목적지 선택은 허용하되 AR 안내 시작은 비활성화한다.

### 4.2 AR 화면 탭

#### 화면 구성

- 전체 화면: `CameraX PreviewView`
- 중앙: Google 경로의 다음 웨이포인트를 가리키는 화살표 오버레이
- 상단 상태 영역:
  - 목적지 이름 또는 좌표
  - GPS/방향 신뢰도 상태
- 하단 정보 영역:
  - 남은 경로 거리와 다음 웨이포인트까지의 거리
  - Google 경로 단계에 맞춘 “왼쪽으로 회전”, “직진”, “오른쪽으로 회전” 안내 문구
  - `2D 지도 보기` 버튼
  - `안내 종료` 버튼
- 안전 문구: “주변을 확인하며 이동하세요.”

#### 화살표 표시 규칙

| 상대 각도 | 화면 표시 |
|---:|---|
| -15° ~ +15° | 위쪽 화살표, `직진 방향` |
| +15° 초과 | 각도에 따라 오른쪽으로 회전한 화살표, `오른쪽으로 회전` |
| -15° 미만 | 각도에 따라 왼쪽으로 회전한 화살표, `왼쪽으로 회전` |
| 방향 신뢰도 낮음 | 화살표 숨김, `휴대폰을 천천히 움직여 방향을 확인하세요` |
| GPS 정확도 낮음 | 화살표 약화 또는 숨김, 2D 지도 확인 유도 |

화면 회전은 세로 모드를 PoC 기본으로 고정한다. 화살표의 급격한 떨림을 줄이기 위해 각도에 저역 통과 필터 또는 원형 이동 평균을 적용한다.

## 6. 경로 진행 및 방향 계산 방식

### 6.1 입력값

- 현재 위치: 위도, 경도, 수평 정확도, 측정 시각
- 목적지: 위도, 경도
- Google 보행 경로: 경로선, 단계, 웨이포인트, 거리, 예상 시간
- 활성 웨이포인트: 현재 안내가 가리킬 다음 경로 지점
- 기기 방위각: 진북 기준 0°~360°
- 선택 입력: 이동 중 GPS bearing 및 속도

### 6.2 Google 경로와 웨이포인트

1. 현재 위치와 목적지를 Routes API의 보행 모드로 요청한다.
2. 응답 경로와 각 보행 단계의 종료 좌표를 내부 `OutdoorRoute`와 `Waypoint` 목록으로 변환한다.
3. 지나치게 가까운 연속 지점은 합치고, 실제 방향 전환점과 단계 종료점을 보존한다.
4. 현재 위치가 활성 웨이포인트의 도달 반경에 들어오거나 경로 진행 방향상 통과한 것이 확인되면 다음 웨이포인트로 전환한다.
5. 현재 위치와 Google 경로선 사이의 거리가 이탈 임계값을 지속해서 초과하면 현재 위치부터 경로를 다시 요청한다.

빈 경로, 좌표 누락 또는 보행 경로가 아닌 응답은 AR 안내 입력으로 사용하지 않는다.

### 6.3 다음 웨이포인트 방위각

현재 좌표에서 **활성 웨이포인트**까지의 초기 방위각을 계산한다. Android의 `Location.bearingTo()`를 사용하거나 동일한 구면 삼각법 계산을 캡슐화한다.

```text
waypointBearing = bearing(currentLocation, activeWaypoint)
relativeAngle = normalize(waypointBearing - deviceHeading)
```

`normalize()`은 결과를 `-180° ~ +180°` 범위로 변환한다. 상대 각도가 0°이면 기기가 다음 웨이포인트를 향하고 있으며, 양수는 오른쪽 회전, 음수는 왼쪽 회전을 의미한다.

### 6.4 기기 방향 결정

- 기본: 가속도계와 지자기 센서 또는 회전 벡터 센서로 기기 방위각 계산
- 이동 중 보조: 충분한 속도와 최신 위치가 있을 때 GPS bearing 참고
- 정지/저속: GPS bearing을 단독으로 사용하지 않음
- 자기장 간섭 감지 또는 센서 정확도 저하: 화살표를 확정적으로 표시하지 않음
- 위치의 자북/진북 차이는 적용 API를 검토해 일관된 기준으로 보정

### 6.5 초기 구성값

다음 값은 코드에 하드코딩하지 않고 설정 클래스로 관리하며 현장 테스트 후 조정한다.

| 설정 | PoC 초기값 | 의미 |
|---|---:|---|
| 도착 반경 | 20 m | 이내 진입 시 도착 후보 |
| 웨이포인트 도달 반경 | 8 m | 다음 웨이포인트 전환 후보 |
| 경로 이탈 거리 | 20 m | 지속 초과 시 경로 재요청 후보 |
| 경로 이탈 지속 시간 | 5초 | 순간 GPS 튐으로 인한 재요청 방지 |
| 허용 GPS 정확도 | 25 m | 초과 시 저정확도 상태 |
| 위치 최대 경과 시간 | 10초 | 초과 시 오래된 위치로 판단 |
| 정면 허용 각도 | ±15° | 직진 방향 표시 범위 |
| 최소 GPS bearing 속도 | 1.5 m/s | 미만에서는 GPS bearing 신뢰 안 함 |
| 화살표 갱신 주기 | 최대 10 Hz | UI 갱신 상한 |

도착은 단일 위치 샘플만으로 확정하지 않고, 도착 반경 내 위치가 연속 2회 이상 관측될 때 확정하는 것을 기본으로 한다.

## 7. 기술 구성

### 7.1 Android 구성 요소

| 영역 | 권장 구성 | 책임 |
|---|---|---|
| 화면 컨테이너 | 단일 Activity + Fragment 2개 | 탭과 화면 수명주기 관리 |
| 목적지 검색 | `MapFragment` | Google 지도, 현재 위치, 목적지 선택 |
| AR 화면 | `ArNavigationFragment` | 카메라 미리보기와 화살표 오버레이 |
| 상태 관리 | `NavigationViewModel` | 두 탭이 공유하는 목적지와 안내 상태 |
| 장소 검색 | Places SDK for Android | 건물·장소 검색과 목적지 후보 제공 |
| 경로 공급자 | `GoogleRouteProvider` + Routes API | 보행 경로 조회 및 공통 웨이포인트 변환 |
| 경로 진행 | `RouteProgressTracker` | 활성 웨이포인트, 통과, 이탈과 재요청 판정 |
| 위치 | Fused Location Provider | 포그라운드 위치 갱신 |
| 방향 | SensorManager 기반 `HeadingProvider` | 기기 방위 및 정확도 제공 |
| 카메라 | CameraX | 프리뷰 및 수명주기 결합 |
| 지도 | Google Maps SDK for Android | 2D 지도, 마커, 경로선, 카메라 이동 |

장소명을 표시하려면 지도 탭 지점의 역지오코딩을 선택 기능으로 추가할 수 있다. 역지오코딩이 실패하거나 네트워크가 없으면 위도·경도를 표시해 목적지 선택 자체가 막히지 않게 한다.

## 8. Google Maps API 사용 계획

### 8.1 필수 설정

- Google Cloud 프로젝트 생성
- Maps SDK for Android 활성화
- Places API/Places SDK for Android 활성화
- Routes API 활성화
- 결제 계정 및 사용량 한도 설정
- Android 앱의 패키지명과 SHA 인증서로 API 키 제한
- API 키를 소스 코드에 직접 작성하지 않고 로컬/빌드 설정을 통해 주입
- 저장소에 실제 API 키를 커밋하지 않음

### 8.2 PoC 사용 기능

- 지도 타일 표시
- 지도 카메라 이동 및 확대/축소
- 지도 탭 이벤트
- 현재 위치 레이어 또는 별도 현재 위치 마커
- Places 기반 건물·장소 검색
- 목적지 마커
- Routes API 보행 경로 요청
- 보행 경로선, 단계와 예상 거리·시간 표시
- 경로 단계의 웨이포인트 변환 및 AR 안내 연동

PoC 1차 버전부터 지도 탭의 임의 좌표 선택과 Places 기반 건물 검색을 모두 지원한다. 두 방식 모두 목적지 확정 후 Routes API의 보행 경로를 요청하며, AR 화살표는 변환된 다음 웨이포인트를 기준으로 동작한다.

## 9. 권한 및 예외 처리

| 상황 | 처리 |
|---|---|
| 위치 권한 최초 요청 | 현재 위치와 AR 안내에 필요한 이유를 안내한 뒤 포그라운드 정밀 위치 요청 |
| 대략적 위치만 허용 | 지도는 표시하되 정확도 경고와 제한 상태 표시 |
| 위치 권한 거부 | 수동 지도 탐색 허용, AR 안내 시작 비활성화, 설정 이동 방법 제공 |
| 카메라 권한 거부 | AR 탭 대신 제한 안내 표시, 지도 탭은 계속 사용 가능 |
| GPS 꺼짐 | 위치 설정 확인 안내와 재시도 제공 |
| GPS 정확도 낮음 | 화살표 숨김 또는 약화, 정확도 값과 2D 지도 확인 버튼 표시 |
| 방향 센서 부정확 | 8자 보정 동작을 안내하고 화살표 숨김 |
| Routes API 빈 경로/실패 | AR 안내 시작 차단, 오류와 재시도 또는 목적지 변경 제공 |
| API 할당량 초과/인증 실패 | 원인 식별이 가능한 오류 표시, AR 안내 시작 차단, 설정 점검 안내 |
| 경로 이탈 | 순간 오차를 필터링한 뒤 현재 위치부터 Google 경로 재요청 |
| 지도 네트워크 오류 | 오류와 재시도 표시, 이미 로드된 목적지와 유효 경로 상태 유지 |
| 앱 백그라운드 전환 | 카메라와 센서 갱신 중지, 복귀 시 상태 확인 후 재개 |

백그라운드 위치 권한은 요청하지 않는다. 카메라 영상과 정확한 이동 경로는 저장하거나 서버로 전송하지 않는다.
