# 실내 AR 내비게이션 개발 샘플

**문화관의 현재 기본 정렬:** 폰의 회전 벡터 센서로 구한 자북을 기준으로 실내 그래프를 반시계 85.5° 회전한다(시계 방향 방위각 274.5°). 길찾기와 새 녹화에 공통 적용하며, 문→복도를 바라보는 카메라 방향을 기본 기준으로 사용하지 않는다. 아래 기존 문 기준 설명은 다른 지도 및 이전 동작에 대한 설명이다.

Android Studio에서 이 디렉터리를 프로젝트로 연다. Java 17 / Android API 24+ / 실제 ARCore 지원 기기를 사용한다.

- **길안내 시작**: 기존 2m → 2m → 오른쪽 2m 경로를 AR 경로선으로 안내한다.
- **지도/경로**: 기본 문화관 1~5층 지도 또는 개발용 테스트 지도를 선택한다. POI 출발지·목적지 및 접근성 옵션으로 A*를 실행한다. 호실에 여러 출입구가 있으면 가장 짧은 출입구 조합을 선택하고 결과에 표시한다.
- **이 경로로 AR 미리보기/안내**: 같은 층의 지도 경로를 기존 AR 렌더러에 적용한다. 결과에 표시된 출발 진입점에서 바닥을 인식시킨 뒤 시작한다. 처음에는 AR 화면의 **방향 보정**에서 지도 기준 방향을 설정한다. 문화관은 도면 위쪽이 기준이며 실제 북쪽이 아니다.
- 다층 경로는 계산과 3D 좌표 변환까지 지원한다. 층간 AR 보행 안내와 자동 층 인식은 구현하지 않았다.

지도 제작법·필드·축·정렬·검증·확장 인터페이스는 [IndoorNavGraph 문서](../../docs/indoor-map-format.md)를 참조한다.

예제 데이터: [test_building.indoor.json](app/src/main/assets/maps/test_building.indoor.json)  
문화관 데이터: [munhwagwan.indoor.json](app/src/main/assets/maps/munhwagwan.indoor.json)  
JSON Schema: [indoor-nav-graph-v1.schema.json](../../docs/schema/indoor-nav-graph-v1.schema.json)

문화관 원본은 `ARNavigation/graph.json`이다. 제공된 파일 기준 노드 206개, 호실 64개와 출입구 1개, 사용 가능한 연결 201개다. 원본의 `distance_m`은 모두 null이고 `field_verified`는 false이며, 도면 추정치를 실측값으로 변경하지 않았다. 층간 후보 8개는 제외한다. 높이 y=0은 층별 2D 작업 평면이며 실제 층고가 아니다. 휠체어 접근성도 미확인 상태를 유지한다.

원본 그래프를 현장 확인 결과로 갱신한 뒤 저장소 루트에서 재변환한다(원본은 수정하지 않음):

```powershell
python tools/import_munhwagwan.py ..\ARNavigation\graph.json
python -m unittest discover -s tools -p test_import_munhwagwan.py
```

양수인 실측 거리를 우선하고 없으면 양수인 도면 거리를 사용한다. 두 거리 모두 없거나 원본에서 제외한 연결은 탐색에 넣지 않는다. 층간 연결을 사용하려면 별도의 높이·정렬 및 이동 정책 구현이 필요하다.

검증:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
.\gradlew.bat :app:connectedDebugAndroidTest
```

원본 Google ARCore 샘플의 카메라/세션/OpenGL 기반을 사용한다. 기기 테스트가 실행된 APK를 설치해 현장 측정 경로와 비교한다.


## 수평 및 방향 보정

- **방향 보정 → 현재 방향**: 카메라 정면을 실제 지도 기준 방향으로 향하고 누른다. 문화관은 도면 위쪽, 테스트 지도는 지도 북쪽, 기본 경로는 진행 기준 방향이다. 보정 시 카메라를 수평에 가깝게 들고 복도를 바라본다. 이후 안내 시작은 다른 기울기·방향에서도 가능하다.
- **방향 보정 → 방위 저장**: 기준 방향의 측정된 **자북 방위(시계 방향 0~360°)**를 입력한다. 진북 방위를 쓰려면 현장 편각을 별도로 반영해야 한다. 실제 문화관 방위는 제공되지 않았으므로 임의 값을 설정하지 않는다.
- 기준 방위는 지도 자산별로 저장한다. 지도 화면의 회전각은 저장된 기준에 추가되는 회전이다. ‘현재 방향’은 센서가 불안정하거나 없어도 현재 AR 세션에서 작동한다. 이 경우 영구 방위는 삭제되고 앱을 다시 열면 재보정해야 한다. 센서가 정상일 때는 측정한 기준 방위도 저장한다.
- 수평은 ARCore의 중력 정렬 +Y로 처리한다. 방위는 회전 벡터의 ENU 좌표계와 `Frame.getAndroidSensorPose()` 좌표계를 대응시킨다. 화면 회전이나 카메라 이미지 센서 축을 방위 축으로 가정하지 않는다. 카메라가 바닥/천장을 향해도 수평 성분이 큰 기기 축을 선택한다.
- 회전 벡터는 AR 프레임과 50ms 이내인 샘플만 사용한다. 정확도 MEDIUM 미만 또는 방위 오차 추정 20° 초과이면 자동 방위 시작을 보류한다. 센서가 없거나 실내 자기장 간섭이 크면 현재 방향으로 보정한다. 보정된 세션 내 방향은 시작할 때마다 센서값으로 덮어쓰지 않는다.
- 인식된 상향 수평면의 영역에서 출발 위치까지의 수평 거리가 3m 이내이고 카메라보다 0.4~2.5m 아래일 때 시작한다. 휴대폰 바로 아래가 인식 영역 밖이어도 앞쪽의 가까운 바닥 높이를 사용할 수 있다. 경로 출발 위치는 휴대폰 위치에 유지한다. 여러 면이면 가장 낮은 면을 사용한다. ARCore 평면 인식만으로 바닥과 가구를 의미적으로 구분할 수 없으므로 **현장에서 바닥인지 확인**해야 한다. 인식된 면 2cm 위에 경로를 표시한다. 바닥 높이를 고정된 휴대폰 높이로 추정하지 않는다.
- 시작 후에는 경로용 월드 앵커를 유지한다. 수동 보정 방향도 별도 앵커로 보관하여 세션의 좌표 보정에 따라 갱신한다. 같은 지도의 다른 경로를 선택하거나 초기화해도 세션 보정을 유지한다. 렌더링과 위치 계산 모두 앵커의 pitch/roll을 제거한 같은 좌표계를 사용한다. 출발 위치는 기존과 같이 수동으로 맞추며, 자동 절대 위치 추정은 제공하지 않는다. 방향 재보정 또는 기준 방위 저장은 진행 중 안내를 초기화한다.

현장 검증(실제 ARCore 지원 기기 필요):

1. 지정 출발점과 복도 기준 방향에서 한 번 방향 보정하고 바닥을 인식시킨다.
2. 초기화 후 같은 위치에서 0°/90°/180° 방향으로 각각 시작한다. 좌우 기울기와 상하 기울기, 카메라가 바닥을 향하는 자세도 반복한다.
3. 경로가 같은 바닥 높이와 실제 기준 방향에 생성되는지 확인한다. 시작 뒤 제자리 회전과 이동에서도 경로가 움직이지 않는지 확인한다.
4. 앱을 재실행하여 저장 방위와 지도별 분리가 유지되는지 확인한다. 철제 구조물 근처, 센서 부정확/미지원 상태에서는 안내 대기 또는 세션 수동 보정을 확인한다.
5. 테이블·계단·다른 층이 바닥으로 선택되지 않는지 확인하고, 잘못된 면이면 시작하지 말고 해당 바닥을 다시 인식시킨다.

공식 좌표계 근거: [ARCore Frame](https://developers.google.com/ar/reference/java/com/google/ar/core/Frame), [Android SensorManager](https://developer.android.com/reference/android/hardware/SensorManager).


## ARCore 녹화 및 재생 (개발/테스트)

AR 화면의 작은 **개발/테스트** 영역에서 사용한다. 기존 지도/경로·길안내 시작·초기화 버튼은 동일하다.

1. **AR 녹화 시작**을 누르면 출발 지점 선택 창이 열린다. **지도 → 층 → 출발 노드**를 선택하고 해당 실제 위치에 서서 **이 지점에서 녹화 시작**을 누른 뒤 이동한다. 복도·문·계단 진입부 등 지도에 저장된 모든 노드를 선택할 수 있다. 출발지를 기록하지 않으려면 **지정 없이 녹화**를 누른다. **녹화 중 ●**와 **녹화 종료**, 선택한 출발 지점이 표시된다.
2. **녹화 종료**를 누르면 ARCore가 MP4를 정상 종료한다. **AR 녹화 데이터**에서 파일명, 시작/종료 시각, 시간, 크기, 출발 지점 및 저장 상태를 확인한다.
3. 목록의 **재생**은 일반 동영상 플레이어가 아니라 새 ARCore Session의 `setPlaybackDatasetUri()`로 데이터를 연다. 화면에 **AR 재생 모드**가 계속 표시된다. 같은 Frame → Camera Pose → 기존 내비게이션/렌더러 경로를 사용한다.
4. **재생 종료**는 재생 Session을 닫고 새 Live AR Session으로 돌아간다. 파일 끝에서도 재생 모드를 유지하므로 실제 카메라로 조용히 전환되지 않는다.
5. 목록의 **삭제**로 파일과 저장 정보를 함께 삭제한다. 사용 중인 파일의 삭제는 막는다.

저장 위치는 앱 내부 `files/ar_recordings/`이며, MP4 파일명에는 시각과 UUID를 넣는다. UUID별 JSON에 recording id, 절대 파일 경로, 시작/종료 시각(epoch ms), 단조 시계 기반 녹화 시간(ms), 파일 크기(bytes), 상태 및 오류를 저장한다. 외부 저장소 권한은 추가하지 않는다. 앱 삭제 시 녹화도 삭제되므로 앱은 업데이트 설치한다.

`ArDatasetController`가 LIVE / RECORDING / PLAYBACK을 관리하며 RECORDING ↔ PLAYBACK 직접 전환은 거부한다. `ArRecordingStore`가 파일과 저장 정보의 영속성·삭제·비정상 종료 복구를 담당한다. Route/Location API 및 경로 탐색 로직을 변경하지 않는다. 녹화에는 ARCore 카메라와 재생에 필요한 기본 센서 데이터가 포함된다. 추가로 앱의 자기 방위 회전 행렬을 UUID custom track에 기록한다. 재생 시에는 해당 녹화의 방위 데이터만 사용하고 현재 폰의 카메라/방위 센서값을 혼합하지 않는다. 녹화 당시 방위 센서가 불안정했다면 재생 화면에서 기존 ‘현재 방향’ 보정으로 기준을 잡는다.

녹화는 ARCore 데이터 기록이며 화면 UI나 길찾기 선택/버튼 조작의 자동 재연은 아니다. 재생 화면에서도 원하는 지도 경로를 선택하고 방향 보정·길안내 시작을 수행한다. 소스 전환 시 이전 세션의 앵커는 폐기하고 선택된 경로는 유지한다. 실시간·재생에서 같은 기존 경로 렌더러를 사용한다. ARCore의 평면 인식과 추적 결과는 재생마다 조금 달라질 수 있다.

Lifecycle 및 오류:

- 녹화 중 Activity pause/background/정상 종료 시 GL 스레드를 멈추고 `stopRecording()`으로 flush한 뒤 AR 세션을 pause한다. `setAutoStopOnPause(true)`도 설정한다.
- 재생 중 background로 이동하면 재생 Session을 닫는다. 복귀 시 같은 파일을 **처음부터 재생**한다. ARCore는 pause 동안 지나간 데이터 프레임을 다시 처리하지 않으므로 끊긴 재생을 그대로 이어 붙이지 않는다.
- 기존 세로 화면/화면 회전 설정을 유지한다. Activity가 재생성되면 Live로 복귀하며 저장된 목록은 유지된다.
- 프로세스 강제 종료 등으로 정상 종료를 확인하지 못한 데이터는 다음 실행 때 비정상 종료 상태로 표시하고 재생을 막는다. MP4는 임의로 지우지 않는다.
- 시작 전 128MB 이상의 여유 공간을 확인한다. 녹화 중 1초마다 확인하여 32MB 미만이면 정상 종료를 시도한다. ARCore 오류·파일 flush 실패·저장 정보 쓰기 실패는 알림과 실패 상태로 처리한다. 저장 정보는 임시 파일과 백업으로 교체하며 다음 실행 때 백업을 복구한다.
- 손상되었거나 ARCore 데이터가 아닌 파일은 오류를 표시하고 새 Live AR Session으로 복귀한다.

검증은 단위 테스트와 `ArDatasetIntegrationTest`에서 수행한다. 실제 연결 기기에서 ARCore 녹화, 다중 트랙 MP4 생성, 화면 종료/재실행 후 목록 유지, ARCore 재생 Frame/pose, 같은 경로 렌더러의 OpenGL draw, 재생 pause/resume, Live 복귀, 재생 후 다시 녹화, 녹화 pause 시 정상 종료, 손상 데이터 거부, 삭제를 검사한다. 저장 공간 부족은 테스트용 공간 값 공급자로 주입하며 실제 기기의 저장소를 채우지 않는다. 이동하며 기록한 실내 보행 경로의 정확도는 별도 현장 검증이 필요하다.

앱과 저장 데이터를 보존하는 기기 테스트는 `assembleDebugAndroidTest` 후 두 APK를 `adb install -r`로 설치하고 `am instrument`로 실행한다. `connectedDebugAndroidTest`의 자동 앱 제거는 사용하지 않는다.

공식 API: [Android Recording & Playback](https://developers.google.com/ar/develop/java/recording-and-playback/developer-guide), [Session](https://developers.google.com/ar/reference/java/com/google/ar/core/Session), [RecordingConfig](https://developers.google.com/ar/reference/java/com/google/ar/core/RecordingConfig).


녹화 출발 지점은 JSON의 선택적 `startPoint` 필드에 지도 자산 경로·지도 ID/이름·층 ID/이름·노드 ID/표시 이름/유형·X/Y/Z 지도 좌표의 사본으로 저장한다. 같은 노드 선택을 다시 사용할 수 있도록 마지막 선택을 지도별로 기억한다. 녹화 목록과 재생 화면에도 저장된 출발 지점을 표시한다. 기존 녹화나 ‘지정 없이 녹화’의 출발 지점은 미지정으로 표시하며 계속 재생할 수 있다. 출발 위치는 수동으로 지정하며 길찾기의 출발 POI는 바꾸지 않는다. 문·진입 노드의 출발 방향은 아래 규칙으로 자동 계산해 같은 지도 경로의 AR 방향에 적용한다. 문화관 Y=0은 층별 작업 평면으로 실제 층고가 아니다.


### 문·진입점에서 복도 쪽을 기준으로 녹화

문·열린 진입부·계단 진입 노드를 선택하면 같은 층의 사용 가능한 링크를 따라 복도로 나가는 방향을 계산한다. **해당 실제 지점에서 표시된 다음 노드 쪽을 바라보고 카메라를 수평에 가깝게 든 채 녹화 시작을 누른다.** 위치 추적이 안정되지 않았거나 카메라가 바닥·천장에 너무 가까운 방향이면 메시지를 표시하고 녹화를 시작하지 않는다. UI에서 선택한 방향을 실제 폰이 바라보는지 자동 인식하는 기능은 아니다.

- `startPoint.direction`에 다음 노드 ID, 도달할 복도 노드 ID, 정규화된 지도 좌표 기준 회전각을 저장한다. 지도 축은 기존 좌표 변환기를 사용해 정규화하며 자북 각도로 간주하지 않는다.
- 일반 문은 연결된 복도 노드 쪽을 사용한다. 406호는 내부 접근 노드가 아닌 직접 연결된 복도 쪽을 선택한다. 406-1호처럼 내부 통로를 거쳐야 하면 복도로 나가는 경로의 **첫 구간**을 사용하며, 최종 복도와 직선으로 연결해 벽을 가로지르는 방향을 만들지 않는다.
- 같은 길이의 출구 방향이 다르거나 복도로 나갈 유효한 같은 층 경로가 없으면 방향을 임의로 선택하지 않는다. 복도 노드 자체와 기존 녹화는 기존 방향 보정을 사용한다.
- 시작 순간 카메라 정면과 계산된 문→복도 방향을 대응시켜 **도면 기준 전체 지도의 회전**을 구한다. 카메라 회전을 그대로 도면 위쪽 방향으로 취급하지 않는다. 녹화 시작 시 같은 지도의 진행 중 안내는 초기화하며, 기존 선택 경로와 추가 회전각은 유지한다. 다른 지도에 이 보정을 적용하지 않는다. 녹화 종료 후 같은 세션에서도 보정 기준은 유지한다.
- 새 MP4에는 지도 기준 앵커에 대한 Android 센서 좌표계의 상대 회전(quaternion)을 별도 ARCore custom track으로 기록한다. 재생 시 해당 프레임의 녹화된 상대 회전과 재생 세션의 Android sensor pose로 기준을 복원한다. 녹화 때의 월드 yaw 숫자를 다른 세션에 그대로 복사하지 않는다. 라이브 센서는 사용하지 않는다.
- 출발 방향이 기록된 재생 데이터는 같은 지도에서 기준 복원을 기다린 뒤 안내를 시작한다. 사용자가 명시적으로 방향 보정 또는 기준 방위를 설정하면 그 수동 보정을 우선한다. 예전 녹화는 새 방향 필드가 없어도 재생된다.

검증: 문화관 문 양쪽의 0°/180° 차이, 406호 분기, 406-1호의 내부 통로, 전체 진입 노드, 일방통행 및 모호한 출구, 폴리라인 첫 구간, 카메라 yaw→도면 기준 변환을 단위 테스트한다. 연결 기기의 실제 녹화/재생에서 지도 기준 앵커 생성·지도별 분리·custom track 복원을 확인한다. 실제 문화관의 문과 링크가 도면에 맞는지는 현장 확인이 필요하다.


### 길찾기에도 출발 문→복도 방향 적용

길찾기는 A*가 실제로 선택한 출발 진입 노드(여러 문 중 선택된 문)를 `EntryDirection`으로 계산한다. 결과 화면에 다음 노드와 복도 방향을 표시하고, 같은 정보를 AR 화면으로 전달한다. 녹화를 하지 않아도 **출발 지점에서 바닥을 먼저 인식시킨 뒤 문에서 표시된 복도 방향을 바라보며 길안내 시작**을 누르면 해당 방향을 기준으로 지도를 정렬한다. 바닥을 기다리는 동안에는 별도 앵커로 시작 순간의 방향을 유지하므로, 이후 바닥을 비추려고 폰을 기울여도 기준을 다시 계산하지 않는다. 시작 버튼을 다시 누르면 현재 방향으로 새로 잡는다.

카메라를 거의 수직으로 향한 채 시작하면 방향 안내를 표시하고 시작 요청을 취소한다. 수평에 가깝게 들어 다시 누른다. 자동 방향을 구할 수 없는 노드는 기존 지도 방향 보정을 사용한다. 기존 추가 회전각은 좌표 변환에 한 번만 적용하며, 출발 방향 값을 전달하면서 경로 좌표를 다시 회전하지 않는다. 녹화 재생 중 같은 지도의 저장된 정렬이 있으면 이를 우선하며, 사용자가 별도로 방향 보정을 선택하면 그 보정을 우선한다. 경로 탐색 거리와 선택 정책은 바꾸지 않는다.


## 문화관 센서 정렬: 반시계 85.5°

사용자가 제공한 건물 방향을 `MapOrientation.MUNHWAGWAN_CCW_DEGREES = 85.5`로 설정했다. Android `TYPE_ROTATION_VECTOR`의 자기 북쪽(자북)을 0°로 해석한다. 도면 위쪽을 자북에서 반시계 85.5°로 돌리므로 시계 방향 방위각은 274.5°이다. ARCore +Y 회전값은 `sensorNorthYaw + radians(85.5)`이다. 도면 오른쪽은 방위각 4.5°가 된다. 이 값은 진북 편각 보정이나 현장 측량값을 자동 추정한 결과가 아니며 사용자 지정 방향이다.

- 문화관 길찾기에서는 시작 순간 카메라가 보는 방향이나 진입 노드의 문→복도 각도로 지도 전체 방향을 결정하지 않는다. 센서 자북과 ARCore Android sensor pose를 대응시킨 뒤 85.5°를 한 번 더해 수평 앵커를 만든다. 바닥을 기다리는 동안에는 이 앵커로 방향을 유지하고 시작 후에는 기존 고정 앵커로 렌더링한다. 도면 좌표/노드/링크를 미리 회전하지 않는다.
- 문화관 녹화는 문·복도 등 어떤 노드를 선택하더라도 같은 센서 기준을 사용한다. 폰을 문→복도 방향으로 맞추거나 수평으로 들 필요는 없다. AR 추적과 방위 센서 정확도가 충분해야 시작하며, 불안정하면 오류를 표시한다. 출발 위치는 여전히 수동 지정이다. 출발 방향은 그래프를 따라 계산한 복도 쪽 방위각으로 표시할 수 있지만, 이 각도를 전체 지도에 다시 더하지 않는다.
- 새 녹화의 JSON에 `mapOrientationSource=MAGNETIC_NORTH_CCW`, `mapCounterClockwiseDegrees=85.5`를 저장한다. 이 기준으로 잡은 앵커와 센서 좌표계의 상대 quaternion을 MP4 custom track에 기록하고 재생 시 복원한다. 복원된 지도에 85.5°를 다시 더하지 않는다.
- 이전의 문 기준 녹화는 기존 앵커를 새 센서 기준이라고 간주하지 않는다. 그 파일의 녹화된 자기 방위 track이 있으면 85.5° 기준으로 다시 계산한다. 기록된 방위가 없으면 명시적 수동 방향 보정이 필요하며 재생 중 현재 폰의 라이브 방위를 섞지 않는다.
- 지도 화면의 **추가 회전각**은 기본 0°다. 기존과 같이 사용자가 지정한 값만 경로 좌표에 한 번 적용한다. **방향 보정**에서 사용자가 직접 지정한 수동 방위/현재 방향은 센서 기본값 대신 사용하며, 이때 85.5°를 다시 더하지 않는다. 과거에 저장된 방위 값은 문화관 기본 센서 정렬을 자동으로 덮어쓰지 않는다.
- 개발용 지도와 기본 테스트 경로는 기존 설정을 유지한다.

검증은 반시계 부호(지도 위쪽이 서쪽으로 회전), 방위각 274.5°, 임의 AR 원점 방향, 폰 yaw/pitch/roll 조합, 추가 각도 중복 방지, 녹화 정책 구분 및 영속성을 포함한다.
